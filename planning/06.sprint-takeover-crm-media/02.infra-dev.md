# Sprint Takeover CRM (Media) — infra-dev

> Diseño: [../07-modo-humano-takeover-crm.md](../07-modo-humano-takeover-crm.md) (§4.2, §4.3, §8)

## Objetivo

Persistencia de media y del historial unificado de conversación, más el backend de
almacenamiento de archivos.

---

## Tareas

### IM-1: Modelo `media_asset` + migración

Campos (ver §4.2): `id (uuid)`, `tenant_slug`, `wa_id`, `direction`, `meta_media_id`,
`mime_type`, `storage_path`, `sha256`, `created_at`, `expires_at` (nullable, sin uso si retención=0).

- Índice por `(tenant_slug, wa_id)` y por `sha256` (dedupe).

### IM-2: Modelo `conversation_message` + migración

Campos (ver §4.3): `id`, `tenant_slug`, `wa_id`, `direction`, `sender`
(`patient|agent|human:<advisor>`), `type`, `text`, `media_asset_id` (FK nullable),
`wa_message_id` (único para idempotencia), `created_at`.

- Índice `(tenant_slug, wa_id, created_at)` para el historial paginado.
- Único en `wa_message_id` (dedupe de reintentos de Meta).

### IM-3: `media_store` service

Archivo nuevo: `app/services/media_store.py`

- Backends: `local` (dir configurable) y `s3` (bucket configurable).
- `save(bytes, mime, tenant, wa_id, direction) -> media_asset` (calcula sha256, deduplica).
- `open(asset_id) -> stream` para servir.
- **Retención indefinida** (no implementar borrado; dejar `MEDIA_RETENTION_DAYS=0` como no-op).

---

## Criterios de aceptación

- Migraciones aplican y revierten limpio.
- Guardar dos veces la misma media (mismo sha256) no duplica archivo.
- Historial consultable por `(wa_id, created_at)` eficientemente.

## Notas

- En dev: backend `local` bajo un volumen; en prod: S3 (o volumen persistente con backup).
- La media es **PII médica**: el directorio/bucket no debe ser público.
