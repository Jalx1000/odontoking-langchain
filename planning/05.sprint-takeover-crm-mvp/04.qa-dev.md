# Sprint Takeover CRM (MVP) — qa-dev

> Diseño: [../07-modo-humano-takeover-crm.md](../07-modo-humano-takeover-crm.md) (§13)

## Objetivo

Cubrir con tests el switch del agente, el ruteo entrante según el flag, la mensajería
saliente del asesor y la ventana de 24 h. Sin mockear la DB para la lógica de estado.

---

## Tareas (tests a escribir)

### Q-1: `conversation_control` (unit)

- Crea fila default `agent_enabled=true` si no existe.
- `set_agent_enabled` persiste y `updated_at` cambia.
- `is_window_open`: true dentro de 24 h, false fuera (parametrizar `last_inbound_at`).

### Q-2: Ruteo del webhook según flag (unit/integration)

- Agente **OFF**: entrante NO invoca al agente (`get_response` no llamado) y SÍ dispara push `message_in`.
- Agente **ON**: comportamiento actual intacto (encola/process_fn) — test de regresión.
- `touch_inbound` actualiza `last_inbound_at`.

### Q-3: Endpoints CRM (integration con TestClient)

- `POST /agent` cambia el flag; `GET /status` lo refleja con `window_open`/`window_expires_at`.
- `POST /messages` (texto): auto-OFF del agente + `send_text_message` invocado + push `message_out`.
- Ventana cerrada → `409 service_window_closed`.
- Sin `X-CRM-Key` → 401/403.

### Q-4: Re-chequeo de takeover (unit)

- Si `agent_enabled` pasa a False durante el procesamiento, el agente **no** envía respuesta.

### Q-5: Regresión CRM-desactivado

- Con `CRM_PUSH_ENABLED=false`, el flujo del agente actual no cambia y no hay llamadas push.

---

## Criterios de aceptación

- Todos los tests del sprint en verde y corriendo en CI (`uv run pytest`).
- Cobertura de los 3 flujos críticos: toggle, entrante-OFF, salida-humano + ventana.
