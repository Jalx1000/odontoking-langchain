# Sprint 4 — qa-dev tasks

## Objetivo

Validar end-to-end el routing por tenant del webhook de WhatsApp:

1. Tenant CON `agent_endpoint_url` → el platform publica a RabbitMQ. No invoca el agente interno.
2. Tenant SIN `agent_endpoint_url` → el platform procesa internamente (buffer + `process_fn`). No toca el broker.
3. El contrato del mensaje publicado tiene exactamente los campos esperados por el worker externo: `wa_id`, `text`, `message_id`.

---

## Tareas

### Q-1: Test suite del routing (`tests/api/test_sprint4.py`)

Archivo nuevo: `tests/api/test_sprint4.py`.

Tests requeridos:

1. **`test_external_tenant_publishes_to_broker`**
   - Setup: stub de `TenantConfig` con `agent_endpoint_url="https://agent.example/webhook"`.
   - Mock de `app.core.broker.broker` con `publish = AsyncMock()`.
   - Mock de `message_buffer_service.enqueue` con `AsyncMock()`.
   - POST al webhook con payload de texto.
   - Asserts:
     - `broker.publish.await_count == 1`
     - argumentos: `tenant.slug`, `wa_id="591701234567"`, y payload dict `{"text": "Hola, necesito un turno", "message_id": "msg-id-1"}`
     - `message_buffer_service.enqueue.await_count == 0`

2. **`test_internal_tenant_uses_buffer`**
   - `TenantConfig` con `agent_endpoint_url=""` (o None).
   - Mock de `broker.publish = AsyncMock()`.
   - Mock de `message_buffer_service.enqueue = AsyncMock()`.
   - POST al webhook con payload de texto.
   - Asserts:
     - `broker.publish.await_count == 0`
     - `message_buffer_service.enqueue.await_count == 1`

3. **`test_published_message_contract`**
   - Mismo setup que test 1, capturar `broker.publish.call_args`.
   - Validar que el dict pasado tiene exactamente los keys: `text`, `message_id` (wa_id se pasa como segundo posicional).
   - Validar tipos: `text` es `str` no vacío; `message_id` es `str` no vacío.

### Convenciones de los tests

- Usar `unittest.mock.patch` para parchear `broker` y `message_buffer_service` antes de importar `app.main`.
- Reusar el patrón de `tests/api/test_internal.py` para el `app_client` fixture (mock de dependencias externas en el `with` block).
- Usar la fixture `sample_whatsapp_text_payload` de `tests/conftest.py`.
- Stubbear `get_tenant_async` con `AsyncMock(return_value=<TenantConfig>)` por test.
- Stubbear `mark_as_read`, `send_response`, `send_typing_indicator` con `AsyncMock()` para evitar llamadas a la API de WhatsApp.
