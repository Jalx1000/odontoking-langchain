## Objetivo

Corregir los problemas estructurales detectados en el proyecto `03.agent-production` y cerrar las brechas de contrato entre backend, worker y frontend.

## Hallazgos Priorizados

### P0 - Aislamiento multi-tenant roto

Problema:

- El historial de conversaciones usa `wa_id` como identificador global.
- El buffer de mensajes también usa claves globales por `wa_id`.
- El panel administrativo consulta conversaciones sin filtrar por tenant real.

Impacto:

- Mezcla de estado entre tenants.
- Riesgo de exponer conversaciones cruzadas.
- Posible corrupción lógica de sesiones si dos tenants comparten identificador.

Acciones:

1. Incluir `tenant_slug` en el `session_id` persistido o en una columna separada.
2. Cambiar las claves del buffer a un namespace por tenant.
3. Filtrar consultas admin por tenant antes de listar o abrir conversaciones.
4. Actualizar tests para cubrir aislamiento entre tenants.

### P0 - Worker incompatible con RabbitMQ

Problema:

- `create_broker()` prioriza RabbitMQ cuando está configurado.
- `app/worker.py` aborta si el broker no es Redis Streams.

Impacto:

- La configuración declarada como soportada no funciona en runtime.
- Un despliegue con RabbitMQ se detiene aunque el broker exista.

Acciones:

1. Eliminar la dependencia rígida a `RedisStreamBroker` en `app/worker.py`.
2. Adaptar el worker para aceptar el broker abstracto.
3. Validar el consumo con RabbitMQ en tests unitarios.
4. Revisar métricas y DLQ para ambos backends.

### P1 - Delete de tenants rompe en frontend

Problema:

- El backend devuelve `204 No Content`.
- El helper HTTP del frontend siempre intenta parsear JSON.

Impacto:

- El delete puede considerarse fallido en UI aunque el backend lo haya ejecutado.

Acciones:

1. Hacer que el helper soporte respuestas vacías.
2. Mantener compatibilidad con endpoints que sí devuelven JSON.
3. Agregar cobertura para `204`.

### P1 - Export CSV de billing no autentica bien

Problema:

- El backend exige `X-Admin-Key`.
- El frontend genera un link con query param `key`.

Impacto:

- La exportación CSV no puede funcionar desde la UI.

Acciones:

1. Cambiar export CSV a una llamada `fetch` con header admin.
2. O bien aceptar un token explícito por header en el backend y estandarizarlo.
3. Eliminar el uso de `?key=` para evitar contratos dobles.

### P2 - Borrado de usuario incompleto

Problema:

- La ruta promete borrar usuario y sesiones.
- El código solo elimina el usuario.

Impacto:

- Riesgo de integridad referencial y comportamiento inconsistente.

Acciones:

1. Definir cascada explícita en ORM o borrar sesiones antes del usuario.
2. Verificar la política real de FK en la base.
3. Agregar test de borrado con sesiones existentes.

## Orden Recomendado

1. Aislamiento multi-tenant.
2. Compatibilidad del worker con RabbitMQ.
3. Corrección de contratos frontend.
4. Borrado consistente de usuarios.
